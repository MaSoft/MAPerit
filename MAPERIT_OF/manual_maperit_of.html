● Adquisición Offline

MaPeriT.OF

Adquisición Forense Offline Profesional sobre disco montado o entorno Live
📄 v1.1.2 🔎 RFC 3227 · NIST SP 800-86 🔗 Compatible con MaPeriT.AN 🔒 Sin escritura en el disco objetivo

Introducción

MaPeriT.OF es la herramienta de adquisición forense offline del ecosistema MaPeriT. Permite recopilar evidencias digitales de un disco duro conectado físicamente a un equipo forense o accesible desde un entorno Windows Live, sin necesidad de arrancar el sistema operativo del disco objetivo.

ℹ
Posición en el ecosistema MaPeriT:
MaPeriT.SW recopila datos de un equipo encendido (datos volátiles incluidos). MaPeriT.OF recopila datos de un disco apagado/montado (sin datos volátiles). Ambas herramientas organizan la salida en las mismas carpetas por fase, compatible con MaPeriT.AN y MaPeriT.TN. El contenido no es idéntico: OF no tiene datos volátiles y extrae del registro offline solo una parte de lo que SW obtiene en vivo.

💾 MaPeriT.SW

Adquisición en caliente. El sistema objetivo está encendido y corriendo. Captura datos volátiles (RAM, procesos, red) además de datos persistentes. Requiere ejecutarse sobre el propio equipo.

🆕 MaPeriT.OF

Adquisición offline. El disco objetivo está montado en otro equipo o accesible desde Live CD. El SO del disco no está en ejecución. Recopila datos persistentes (fases 2–10) sin alterar el disco.

📊 MaPeriT.AN

Análisis profundo offline. Procesa la carpeta de evidencias generada por SW o OF. Parsea $MFT, analiza EVTX, extrae SQLite de navegadores y genera informe correlacionado.

Características principales

💾

Adquisición de $MFT completo

Copia la Master File Table del disco objetivo usando privilegio de backup, preservando metadata NTFS para análisis por MaPeriT.AN.

🔓

Registro offline vía reg load

Copia los hives SYSTEM, SOFTWARE, SAM, SECURITY, DEFAULT, NTUSER.DAT y UsrClass.dat como evidencia y, para consultar sus valores, monta una copia de trabajo (nunca el fichero original del disco objetivo), que se desmonta y se borra al terminar.

📄

Copia de logs de eventos (.evtx)

Copia hasta 200 ficheros .evtx priorizando Security, System, PowerShell y acceso remoto, listos para análisis por MaPeriT.AN.

🌐

Artefactos de navegadores

Extrae History, Cookies, Login Data y Bookmarks de Chrome, Edge, Brave y Firefox para todos los perfiles de usuario detectados.

👥

Multi-usuario automático

Detecta y procesa todos los perfiles de Users\ automáticamente, o filtra a un usuario específico con -TargetUser.

🔗

Salida 100% compatible con AN

Usa las mismas carpetas por fase que MaPeriT.SW y los ficheros de referencia que leen AN y TN (HashManifest.csv, OSInfo.json, $MFT, Amcache.hve, .evtx, navegadores en <navegador>\<usuario>\<perfil>).

🔒

Firma HMAC-SHA256

Firma criptográfica opcional del manifiesto de evidencias con clave secreta compartida. Garantiza integridad verificable en sede judicial.

🔍

Mecanismos de persistencia

Detecta autoarranque, tareas programadas, IFEO, AppInit_DLLs, BAM/DAM y servicios leyendo directamente del hive del disco objetivo.

📈

Cadena de custodia automática

Cada fichero copiado queda registrado con su hash SHA-256, ruta origen/destino y método de adquisición en HashManifest.csv.

📝

Informe HTML judicial

Genera InformePericial.html con identificación del caso, metodología, fases ejecutadas y estadisticas, listo para adjuntar a un informe pericial.

Preparación del disco objetivo

⚠
Buenas prácticas forenses: Para garantizar la admisibilidad de las evidencias, conecte el disco mediante un write blocker hardware antes de montarlo en el equipo forense. MaPeriT.OF no escribe en el disco objetivo, pero el SO del equipo forense puede hacerlo si no hay bloqueador.

Pasos de preparación

1
Conectar disco
SATA, USB o mediante adaptador con write blocker
2
Anotar letra
Verificar en Administrador de discos la letra asignada (D:, E:…)
3
Abrir PowerShell
Como Administrador. Configurar política de ejecución
4
Ejecutar OF
Con -TargetDisk y datos del caso
5
Procesar con AN
Apuntar AN a la carpeta de salida de OF
# 1. Verificar que el disco es accesible y tiene Windows
Test-Path "E:\Windows\System32"   # Debe devolver True

# 2. Configurar politica de ejecucion para la sesion actual
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass

# 3. Navegar a la carpeta de MaPeriT.OF
cd "I:\Herramientas\MAPERIT\MAPERIT_OF"

Flujo de trabajo completo

MaPeriT.OF está diseñado para encajar en el flujo forense estándar de dos fases:

Fase de adquisición → Fase de análisis
1
Disco montado
Hardware conectado, letra de unidad asignada
2
MaPeriT.OF
Recoge fases 2–10 del disco offline
3
Carpeta de evidencias
Estructura idéntica a la de MaPeriT.SW
4
MaPeriT.AN
Análisis profundo: MFT, EVTX, SQLite, correlación
5
Informe AN
Informe judicial completo con hallazgos
✓
MaPeriT.AN trabaja igual con OF que con SW: la carpeta generada por OF contiene los ficheros que AN analiza ($MFT, .evtx, Amcache.hve, AppCompatCache.bin, navegadores, OSInfo.json, ForensicLog.csv). Los análisis que dependen de datos que solo existen en vivo (por ejemplo el USN Journal o la timeline de SW) no se generan.

Referencia de parámetros

Parámetro Tipo Estado Descripción
-TargetDisk String Obligatorio Letra de unidad del disco objetivo montado en el equipo forense.
Formato: D:   E:   F:   G:… (con o sin barra final, se normaliza internamente)
-CaseNumber String Obligatorio Número de caso o expediente judicial.
Forma parte del nombre del directorio de salida.
Ejemplos: "JUD-2026-112"   "CASO-0457"
-ExaminerName String Obligatorio Nombre completo del perito informático responsable.
Aparece en el informe HTML y en la cadena de custodia.
-OutputPath String Opcional Directorio de salida para las evidencias.
Por defecto .\MaPeriT_OF_<caso>_<timestamp> en la carpeta del script.
-EvidenceDescription String Opcional Descripción narrativa del encargo pericial. Aparece en el informe HTML y en el fichero de nota OFFLINE_ACQUISITION.txt.
-SkipPhases String Opcional Fases a omitir, separadas por comas o espacios. Rango válido: 2–10.
Ejemplo: "8,9" omite Cloud Storage y USB. Desde v1.1.2 es texto: @(8,9) fallaba al ejecutar con powershell -File.
-CopyLargeFiles Switch Opcional Si se activa, copia ficheros mayores de 500 MB como PST/OST de Outlook.
Sin este flag, los ficheros grandes se registran en el log pero no se copian.
-HMACKey String Opcional Clave secreta para firma HMAC-SHA256 del manifiesto de evidencias.
Genera un fichero adicional HashManifest_HMAC.txt con la firma.
La parte contraria puede verificar la integridad con la misma clave.
-TargetUser String Opcional Exclusivo OF Nombre del perfil de usuario específico a analizar (nombre de carpeta en Users\).
Si se omite, se procesan todos los perfiles detectados automáticamente.
-ExcludePaths String[] Opcional v1.1.0 Fragmentos de ruta a excluir de la copia (subcadena, sin distinguir mayusculas/minusculas). Minimizacion de datos cuando la orden judicial delimita el alcance.
Ejemplo: -ExcludePaths @("\Fotos Familiares\","\Backups Personales\"). Las exclusiones quedan siempre registradas como SKIP en el log.
-VerifyPath String Opcional v1.1.0 Modo verificacion: comprueba la integridad de una adquisicion OF previa contra su HashManifest.csv. No requiere -TargetDisk/-CaseNumber/-ExaminerName.
Funciona aunque la carpeta de evidencias se haya movido o copiado a otra unidad para su presentacion en sede judicial.

Nota: -TargetDisk, -CaseNumber y -ExaminerName solo son obligatorios en modo adquisicion. Al usar -VerifyPath se omiten y no se solicitan.

Ejemplos de ejecución

Adquisición básica

Disco objetivo montado en E:, procesa todos los usuarios:

.\MaPeriT.OF.ps1 -TargetDisk "E:" -CaseNumber "JUD-2026-112" -ExaminerName "Juan Perez Garcia"

Adquisición con salida a unidad externa y descripción

.\MaPeriT.OF.ps1 -TargetDisk "F:" `
    -CaseNumber "CASO-2026-0457" `
    -ExaminerName "Ana Garcia Lopez" `
    -OutputPath "G:\Peritajes\CASO-0457" `
    -EvidenceDescription "Analisis del disco duro del portatil HP del empleado"

Solo un usuario, con firma HMAC judicial

.\MaPeriT.OF.ps1 -TargetDisk "D:" `
    -CaseNumber "JUD-2026-112" `
    -ExaminerName "Maria Fernandez Ruiz" `
    -TargetUser "jsmith" `
    -HMACKey "clave-judicial-2026"

Omitir fases de nube y USB, incluir ficheros grandes

.\MaPeriT.OF.ps1 -TargetDisk "E:" `
    -CaseNumber "INC-789" `
    -ExaminerName "Carlos Martinez" `
    -SkipPhases "8,9" `
    -CopyLargeFiles

Flujo completo OF → AN

# 1. Adquisicion offline
.\MaPeriT.OF.ps1 -TargetDisk "E:" -CaseNumber "JUD-112" -ExaminerName "Juan Perez Garcia"

# 2. Anotar la ruta de salida que muestra OF al finalizar, por ejemplo:
#    .\MaPeriT_OF_JUD-112_20260610_103045

# 3. Analisis profundo con AN
.\MaPeriT.AN.ps1 -EvidencePath ".\MaPeriT_OF_JUD-112_20260610_103045"

Fases de adquisición

ℹ
La Fase 1 (Datos Volátiles) no es ejecutable en modo offline — la RAM, los procesos en ejecución, las conexiones de red y la caché DNS solo existen en un sistema arrancado. OF crea la carpeta 01_Volatile\ con una nota explicativa para que AN no genere errores.
Fase Nombre Qué recopila Técnica Estado
1 Datos Volátiles RAM, procesos, red, DNS, ARP, portapapeles — N/A offline
2 Información del Sistema Versión SO, nombre equipo, zona horaria, último apagado, software instalado, historial de redes reg load sobre copia de trabajo (SOFTWARE + SYSTEM) ✓ Ejecuta
3 Sistema de Ficheros $MFT completo, directorio raíz, Prefetch, ejecutables recientes, Amcache.hve, papelera de reciclaje (ficheros $I/$R y resumen), ficheros sospechosos robocopy /B + Copy-Item ✓ Ejecuta
4 Registro de Windows Run/RunOnce, Winlogon, servicios, último usuario, AppCompatCache (ShimCache), NTUSER.DAT (RecentDocs, TypedPaths, RDP) Copia de hives + reg load sobre copia de trabajo (SYSTEM + SOFTWARE + NTUSER) ✓ Ejecuta
5 Logs de Eventos Hasta 200 ficheros .evtx priorizando Security, System, PowerShell, TaskScheduler, RDP, Defender y Sysmon Copy-Item directo ✓ Ejecuta
6 Navegadores Web History, Cookies, Login Data, Bookmarks de Chrome, Edge, Brave y Firefox (todos los perfiles de usuario) Copy-Item desde AppData ✓ Ejecuta
7 Comunicaciones PST/OST de Outlook, Teams (clásico y nuevo), Skype, Discord (logs, .db, .json) Copy-Item / robocopy ✓ Ejecuta
8 Almacenamiento en la Nube Logs y BD de sincronización de OneDrive, Google Drive y Dropbox por usuario Copy-Item desde AppData ✓ Ejecuta
9 Dispositivos USB USBSTOR (almacenamiento USB), todos los dispositivos USB, MountedDevices (asignación de letras) reg load sobre copia de trabajo (SYSTEM) ✓ Ejecuta
10 Mecanismos de Persistencia Tareas programadas (XML), IFEO/Debuggers, AppInit_DLLs, LSA Providers, BAM, Run keys de usuarios reg load + robocopy /B ✓ Ejecuta

Acceso al registro offline

OF accede al registro del disco objetivo sin arrancarlo mediante el mecanismo reg load de Windows:

1
Localiza hive
Busca SYSTEM, SOFTWARE o NTUSER.DAT en el disco objetivo
2
Copia + reg load
Copia el hive (y sus .LOG1/.LOG2) a Logs\_hives_trabajo y monta esa copia bajo HKLM\OF_xxx; el original nunca se monta
3
Consulta
Lee claves via Registry:: provider de PowerShell
4
reg unload
Libera el hive (GC forzado antes para liberar handles) y borra la copia de trabajo
⚠
Hive bloqueado: Si un hive del disco objetivo está bloqueado por otro proceso (por ejemplo, si el disco se está usando en modo Live con el SO arrancado), reg load fallará. OF registrará el error en el log y continuará con el resto de fases. Los hives solo se bloquean cuando el SO que los usa está en ejecución.

Resolución de problemas

Problema Causa probable Solución
El disco 'X:' no es accesible La letra de disco no existe o el disco no está montado Abrir Administrador de discos (diskmgmt.msc) y verificar la letra asignada al disco. Asegurarse de que la partición NTFS está inicializada.
No se encontró una instalación de Windows La ruta Windows\System32 no existe en el disco objetivo Comprobar que se apunta a la partición del SO, no a una partición de datos o de recuperación. Verificar con dir E:\.
HIVE_ERROR_CARGA en el log El hive está bloqueado (SO del disco en ejecución) o dañado Si el SO está en ejecución, apagarlo primero. Si el hive está dañado, usar chkdsk. OF continuará con el resto de fases.
MFT_NO_COPIADO Robocopy no pudo acceder a $MFT con los privilegios actuales Asegurarse de que PowerShell se ejecuta como Administrador. En algunos entornos Live, el UAC puede estar limitado.
reg unload falla al finalizar Alguna variable de PowerShell retiene un handle al hive OF fuerza [GC]::Collect() antes de desmontar. Si persiste, cerrar PowerShell y ejecutar reg unload HKLM\OF_xxx (la clave exacta figura en Logs\ForensicLog.csv). Un hive montado no se desmonta solo al cerrar la sesión: permanece hasta reg unload o hasta reiniciar. Es una copia de trabajo, no el hive del disco objetivo.
OF genera errores en fases 6–8 pero no falla El usuario objetivo no tiene esas aplicaciones instaladas Comportamiento normal. Los errores de tipo WARNING indican que la ruta no existe. Revisar el log para confirmar.
AN muestra “Caso SW: DESCONOCIDO” Falta Logs\ForensicLog.csv y la carpeta se ha renombrado AN toma el caso de la acción SESION_INICIADA de Logs\ForensicLog.csv o, si no está, del nombre de carpeta MaPeriT_OF_<caso>_<fecha>. Mantener ese fichero y ese nombre. (AN no tiene parámetro -CaseNumber.)
PST/OST no se copian Ficheros mayores de 500 MB omitidos por defecto Usar el parámetro -CopyLargeFiles. Asegurarse de que hay suficiente espacio en el destino.
Error de política de ejecución PowerShell bloquea la ejecución del script Ejecutar Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass antes de lanzar OF. O usar: pwsh -ExecutionPolicy Bypass -File .\MaPeriT.OF.ps1 ...

Registro de cambios

Revisión completa y pruebas reales (v1.1.2, 16/11/2026):
  • Registro: se monta una copia de trabajo de cada hive, nunca el original (antes reg load abría el hive del disco objetivo en lectura-escritura y fallaba con bloqueador de escritura). Los hives completos se conservan ahora como evidencia en 04_Registry\Hives.
  • Paso 3.5 (ejecutables en ubicaciones sospechosas): fallaba siempre por un error de sintaxis en la lista de rutas.
  • Papelera: no se leía nunca (las carpetas por SID son ocultas y de sistema); ahora se copian los $I/$R y se interpreta la ruta original, el tamaño y la fecha de borrado real.
  • Tareas programadas: el resumen no se generaba (las tareas son XML sin extensión).
  • Navegadores: misma organización que SW (<navegador>\<usuario>\<perfil>), la que lee AN; antes AN no analizaba ninguno. Cookies de Chrome/Edge 96+.
  • Amcache.hve se copia para que AN lo analice. La cuenta Administrator ya no se excluye.
  • Informe: muestra el estado real de cada fase (omitida o con error) y la fecha de adquisición real; texto de metodología corregido.
  • -SkipPhases pasa a ser texto ("8,9"); -VerifyPath devuelve código 1 si hay discrepancias; la ruta de salida se normaliza (relativa o abreviada 8.3).
Verificacion end-to-end real y refuerzo de fiabilidad (v1.1.1, 12/07/2026): tras completar la auditoria de las 5 herramientas, se ejecuto una adquisicion OF -> AN -> TN real (disco sintetico montado con subst) para validar el ecosistema completo. Se encontro un fallo real: OF nunca llegaba a cargar System.Web.HttpUtility (a diferencia de SW y AN, que al menos lo intentaban) - el informe pericial se rompia siempre con "No se encuentra el tipo" en cuanto tocaba codificar cualquier campo. Corregido con Common\HtmlEncoding.ps1, compartido con SW y AN, que garantiza el tipo disponible con un reemplazo minimo si el ensamblado real no carga. Ademas: Get-RelativeEvidencePath ahora se comparte con SW en Common\ en vez de mantenerse como copias independientes; corregido un conteo vacio en -VerifyPath con manifiestos de un solo fichero (aplanado de array de PowerShell); y cada Build.ps1 verifica ahora la sintaxis del compilado antes de darlo por bueno.
Auditoria de seguridad y fiabilidad forense (v1.1.0, 12/07/2026): revision completa linea a linea de los 20 ficheros fuente. Un bug corregido y tres mejoras implementadas, verificadas con parseo AST + motor real PowerShell 5.1 y prueba funcional real de -VerifyPath contra un manifiesto sintetico.

Aviso legal

🔒
USO AUTORIZADO EXCLUSIVAMENTE: MaPeriT.OF debe utilizarse únicamente con autorización expresa del propietario del dispositivo o por mandato judicial. El acceso no autorizado a sistemas informáticos o soportes de almacenamiento puede constituir un delito tipificado en el Código Penal (art. 197 y siguientes, LO 10/1995).
Condiciones de uso y limitaciones técnicas
AspectoDetalle
Operaciones sobre disco ✓ OF no escribe en el disco objetivo: los ficheros se copian y los hives se consultan sobre una copia de trabajo, nunca montando el original. La única escritura se realiza en el directorio de salida designado por el perito. El sistema operativo del equipo forense sí puede escribir en un disco conectado: use un bloqueador de escritura.
Integridad de evidencias Cada fichero copiado se verifica con hash SHA-256 y queda registrado en HashManifest.csv. La firma HMAC-SHA256 opcional permite verificación criptográfica de la integridad del conjunto.
Registro de actividad Todas las operaciones quedan registradas en ForensicLog.csv con marca de tiempo, acción y resultado. Este log forma parte de la cadena de custodia.
Datos personales Las evidencias pueden contener datos personales. El tratamiento debe ajustarse al Reglamento General de Protección de Datos (RGPD) y a la LOPDGDD.
Responsabilidad El perito que ejecuta la herramienta asume la responsabilidad de contar con la autorización legal pertinente y de custodiar adecuadamente las evidencias obtenidas.
Write blocker Para uso en procedimientos judiciales, se recomienda encarecidamente el uso de un bloqueador de escritura hardware certificado para garantizar la inalterabilidad del disco objetivo, independientemente del comportamiento del SO anfitrión.
